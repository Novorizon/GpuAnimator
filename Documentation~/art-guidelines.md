# 美术资源交付规范

本文对应 `main` 的 **GpuSkinning > Baker**。先用一个角色通过验证、完成烘焙并确认播放效果，再交付整批角色。工具保留旋转、位移、统一缩放和四权重 LBS 的既有格式，不会把不兼容的模型自动转换为此格式。

## 交付目录

默认源目录为 `Assets/Artworks/GpuRole/`，可在 Baker 窗口修改。源目录的每个直接子目录作为一个角色，目录名为角色名。以 `Hero` 为例：

```text
Assets/Artworks/GpuRole/
└── Hero/
    ├── Character.fbx          # 必须恰好一个 FBX，文件名可与角色名不同
    └── res/
        ├── Hero.png           # 必需：角色主贴图
        ├── Hero_mask.png      # 可选：Shader 使用的遮罩
        ├── Idle.anim          # 至少一个独立的 AnimationClip 资源
        └── Walk.anim
```

主贴图和遮罩的名称取自角色目录名；不要求 `Hero.mat`。输入材质不作为生成材质的模板。FBX 内嵌动作需要先准备为 `res` 目录中的独立 `.anim` 资源；当前目录接口不会自动收集 FBX 的内嵌动画。角色目录中的 FBX、`res` 中的贴图和 `.anim` 都按这一层查找，不递归收集嵌套资源。

资源发现允许扩展名以及 `res`、匹配贴图名称的大小写差异，但拒绝仅大小写不同的重复候选或角色目录。角色目录名不能含 `<>:"/\|?*`、控制字符，或以点、空格结尾。建议交付时统一使用上面的准确拼写，避免跨操作系统和版本管理冲突。播放器按 `AnimationClip.name` 查找动作，而非按文件名；动作名称要稳定、非空且互不重复。

## 必须满足的数据条件

| 项目 | 要求 |
| --- | --- |
| 模型 | 一个 FBX 的完整层级中恰好一个 `SkinnedMeshRenderer`，包括未激活节点；网格恰好一个非空三角形 submesh，索引数至少三个且为三的倍数，SMR 节点不必包含角色名 |
| 骨骼 | bones、bindposes 和顶点索引对应有效；bindposes 数量与 bones 一致、矩阵有限且可逆；`rootBone` 和全部骨骼位于模型层级内 |
| 顶点 | 位置、法线和 UV0 数量完整且有限，法线非零；实际骨骼影响数每顶点最多四个，权重有限、非负且归一化 |
| 骨骼变换 | 每个采样时刻的最终蒙皮矩阵必须能表示为位移、旋转和一个带符号的统一缩放；不能包含独立轴缩放或剪切 |
| 数值范围 | 写入动画纹理的旋转、位移和缩放分量均须有限，且绝对值小于 `128`；这是现有定点编码的范围，不是人物世界位置的限制 |
| 动作 | `.anim` 资源有效，采样帧率和长度有限且大于零，名称唯一，全部采样数据有效 |
| 动画绑定 | Transform 曲线的路径必须存在；不接受对象引用曲线，以及 BlendShape、材质、激活状态等非 Transform/Animator 数值曲线 |
| 默认形变 | 网格可以保留未使用的 BlendShape，但 Renderer 上每个默认 BlendShape 权重必须有限且为零；非零默认形变不会被转换为静态网格 |
| 纹理容量 | 所有 Clip 的骨骼帧数据必须装进窗口配置的最大动画纹理尺寸；目标平台也要支持该尺寸 |

这里约束的是用于烘焙的最终蒙皮矩阵。仅在 DCC 或 Inspector 中看到局部缩放一致，并不能保证经过父级、绑定矩阵和动画组合后仍符合要求；以 Baker 的逐帧验证结果为准。反向缩放或镜像应交由验证检查能否准确表示，不要用忽略错误的方式继续交付。

当前格式每骨骼每帧占用八个 RGBA32 像素，即 `32` 字节。所需有效像素数为 `骨骼数 × 所有 Clip 采样帧总数 × 8`，实际纹理尺寸还受布局取整影响。Shader 使用整数像素索引，避免大纹理的浮点寻址误差；目标 GPU 仍需支持 Shader target 3.5 对应的整数运算、实例化能力及所选纹理尺寸。删除未交付动作、减少不必要骨骼或合理降低烘焙帧率可以减小资源；播放器跳帧不会减小动画 PNG。

## 推荐制作习惯

- 项目统一模型单位、角色朝向和原点约定；通常使用 `1 Unity 单位 = 1 米`，在交付前应用不必要的导出缩放。它是项目约定，不是工具强制的单位制。
- 优先使用正的统一缩放，保持根节点和绑定姿态清晰；避免叠加缩放、极端骨骼位移和复杂镜像层级。
- 将身体、头发、服装和需要一起烘焙的装备预先整理为一个 SMR、一个 submesh，并使用同一套主贴图。工具不会合并多个 SMR 或保留多材质分区。
- 文件、角色和骨骼使用稳定、便于版本管理的名称，推荐 ASCII 字母、数字和下划线；不要只通过修改文件名来改变运行时动作名。
- 循环动作检查首尾姿态衔接、脚底滑动和动作相位；移动速度由业务控制时，优先交付原地动作。
- 交付前检查法线、UV、权重总和和关节扭转。LBS 的大角度扭转体积损失仍会存在，工具不会自动修权重。

## 采样与当前能力边界

循环动作按输入 Clip 的帧率采样，不重复保存时长边界的首尾重复帧。记源长度为 `L`、帧率为 `F`：循环 Clip 生成 `ceil(L × F)` 帧，非循环 Clip 生成 `ceil(L × F) + 1` 帧并保存精确结束时刻。运行时按每帧一个采样间隔播放，因此 `N` 个输出帧的名义完成时间为 `N / F`，包含末帧停留间隔，可能长于源 Clip 的 `length`。不要只用源时长估算完成回调时间。

采样在隔离的预览场景中进行，各 Clip 使用新的模型实例，每帧恢复基准 TRS 后再采样，避免前一动作的缺失轨道污染后一动作。生成网格的 bounds 会覆盖采样动作并增加余量；仍应在实际摄像机和项目实例变换下检查剔除效果。

这些采样与 bounds 改动需要用 3.1 重新烘焙才能应用到旧角色。更新包不会自动修改旧 PNG、Mesh 或 `.bytes`；请成套替换输出，避免新旧资源混用。

当前 Shader 按离散帧播放，不提供帧间插值、Clip 交叉混合或 DQS。导出网格保持固定顶点数据，BlendShape/形变目标动画不包含在骨骼纹理中；相关曲线会被验证拒绝，而非静默丢弃。动画事件、碰撞体和骨骼挂点也不会由此烘焙流程转换为运行时逻辑。含 Animator/肌肉曲线的 Clip 不会仅因 Humanoid 类型被拒绝，但会报告提醒；重定向和 IK 的结果需要在目标 Unity 项目验证。根节点或根骨骼的位移可以影响烘焙出的视觉姿态，播放器不会据此推动 GameObject；导航、位移、碰撞和 Root Motion 的业务处理需要项目接入层负责。

## 单角色验收流程

1. 先建立只含一个角色的源目录，按交付目录放入 FBX、主贴图和 `.anim`。
2. 打开 **GpuSkinning > Baker**，设置源目录、独立的输出目录、Unlit/PBR 和最大动画纹理尺寸，默认上限为 `2048`。源目录与输出目录均须在本项目 `Assets/` 中，不能相同或互相包含。
3. 在非 Play 模式且导入、编译完成后执行 **Validate all roles**。它会完整采样和准备数据，但不会创建、覆盖或删除烘焙输出；根据窗口与 Console 中的角色报告修正错误后重新验证。
4. 执行 **Bake all roles**，检查生成 prefab、Mesh、材质、`_Data.png` 和 `_Data.bytes`，按[快速开始](getting-started.md#首次播放)初始化播放器。
5. 逐个播放实际 Clip 名称，检查首尾、帧率、脚底、扭转、PBR 光照和镜头边缘剔除。对一次性动作额外检查末帧与完成回调；再在目标平台检查纹理导入和批处理情况。
6. 在输入资源不变时重新烘焙一次，确认项目引用仍有效。批量取消会保留已经成功保存的角色；根据结果报告判断剩余角色是否需要重新执行。

生成文件应作为一套资源提交版本管理，并保留 `.meta`。自定义行为和额外组件建议放在包装 prefab 或 prefab Variant 中；生成资源自身仍由烘焙器管理。工具不再删除整个角色输出目录，也会保留未受管理的材质属性，但这不代表会合并所有手工修改。

本次改动的自动化检查不能替代 Unity Editor 的实际导入、烘焙和目标平台渲染验证；尚未在真实 Unity Editor 中完成这组验收。
